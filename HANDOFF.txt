8. GOTCHAS / HARD-WON LESSONS
----------------------------------------------------------------
CHECKPOINT SYSTEM (read before asking anyone to do anything):
- Every request to Charles, Ariel or Olivier gets a checkpoint FILE in
  checkpoints/. Not a chat message, not a task list.
- Two gates: the assignee CLAIMS (edits the file, status CLAIMED +
  evidence), then verify.py independently checks the REAL WORLD. A
  claim whose check fails becomes DISPUTED, not green.
- Statuses: OPEN / CLAIMED / VERIFIED / DISPUTED / BLOCKED / CANCELLED.
  VERIFIED and DISPUTED are written ONLY by verify.py, never by hand.
- THE RULE THAT MATTERS: a check must be FALSE on the day you write it,
  and you run the verifier once to prove it fails. Two of the first 18
  checks were wrong and went green instantly. Anything that passes
  immediately is a bug in the check, not a success.
- verify types: dns, http, http-contains, http-absent, repo-file,
  manual-attest.

WRITING TO THESE REPOS - the environment reality:
- `git push` to gershonconsulting repos is REFUSED by the agent git
  proxy. api.github.com returns 403 on writes. `git clone` and
  raw.githubusercontent.com both work fine (which is what makes
  repo-file verification possible).
- The ONLY working write path is the GitHub web UI driven through
  Chrome (browser 'oattia').
- file_upload is refused when ONE CALL carries MORE THAN ONE FILE.
  Upload one file per call; the page accumulates them; then commit
  once. Paths must be under /mnt/user-data/uploads/ (staged from the
  device) - /mnt/user-data/outputs/ is rejected with a different error.
- A single-file call can be refused at random. Retry once before
  concluding anything is blocked.
- Do NOT inject file content as base64 through javascript_tool; it is
  blocked as obfuscated injection. Typing into the CodeMirror editor
  via execCommand('insertText') DOES work and is the cheapest route
  for a text file.
- The upload page commits into the directory in its URL, so a change
  touching N directories is N commits and N production builds. Instead
  create a branch on the first upload, add the rest to that branch,
  then open and merge one PR = one deploy.
- VERIFY EVERY COMMIT by reading raw.githubusercontent.com. Commits
  have silently failed to land and looked identical to success.
- If Chrome reports Viewport 0x0, STOP. The window has no paint
  surface; coordinate clicks land nowhere and resize_window does not
  fix it. Two 0x0 readings on separate days means tell Olivier the
  extension needs attention rather than silently rescheduling.
